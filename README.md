# OpenSearch Query DSL → ClickHouse SQL

Spring Boot MVC-приложение, преобразующее ограниченный поднабор OpenSearch Query DSL в ClickHouse SQL. MVP только генерирует SQL: он не подключается к базам данных и не выполняет запросы.

## Запуск

Проект использует Spring Boot 4.1.2, Java 21, Maven и springdoc-openapi 3.2.0. Требуются Java 21 и Maven. Сборка и тесты:

```bash
mvn test
```

Запуск приложения:

```bash
mvn spring-boot:run
```

Swagger UI: `http://localhost:8080/swagger-ui.html`.

## API

`POST /api/v1/query/translate`, `Content-Type: application/json`.

```json
{
  "table": "windows_logs",
  "query": {
    "term": {
      "source": "192.168.1.10"
    }
  }
}
```

Ответ:

```json
{
  "sql": "SELECT * FROM windows_logs WHERE source = ?",
  "parameters": ["192.168.1.10"]
}
```

Значения всегда находятся в `parameters` и не подставляются в текст SQL. Имена таблиц и полей берутся из `query-translator.tables` в `application.yml`. Имена таблиц — только простые идентификаторы из allowlist; database-qualified и произвольные имена не допускаются.

## Поддерживаемый DSL

- `term`: точное `=`; значение должно соответствовать логическому типу поля.
- `terms`: непустой список значений того же типа, до 1000 значений по умолчанию.
- `range`: `gt`, `gte`, `lt`, `lte` для `NUMBER` и `TIMESTAMP`; timestamp — ISO 8601 со смещением/часовым поясом. Для одной стороны нельзя задавать одновременно строгую и нестрогую границу.
- `exists`: только обычная колонка; генерируется `IS NOT NULL`. Пустая строка считается существующим значением. Nullable, JSON, Map и отсутствующие ключи в MVP не моделируются.
- `bool`: непустые массивы `must`, `filter`, `should`, `must_not`. `must` и `filter` являются AND-группами; каждый элемент `must_not` отдельно отрицается; `should` всегда является обязательной OR-группой, в том числе вместе с `must` и `filter`. `minimum_should_match` и неизвестные свойства не поддерживаются.
- `wildcard`: для строковых полей; `*` переводится в `%`, `?` — в `_`. Литеральные `%`, `_` и `\` экранируются для SQL LIKE. Генерируется `LIKE ? ESCAPE '\\'`; шаблон остаётся параметром. `case_insensitive` не поддерживается.

Поддерживаются типы полей `STRING`, `NUMBER`, `TIMESTAMP`, `BOOLEAN`. Значения `null`, несовпадающие типы и неизвестные DSL операторы/свойства отклоняются.

## Ошибки и лимиты

- `400` — некорректный JSON или контракт запроса.
- `413` — тело запроса больше лимита.
- `422` — неизвестная таблица/поле, неподдерживаемый оператор, опция или семантически недопустимое значение.
- `500` — неожиданная ошибка с безопасным сообщением без stack trace.

Лимиты задаются через `query-translator.limits` в `application.yml`: размер тела 1 MiB, глубина DSL 10, до 1000 значений `terms`, длина wildcard до 1024 символов. Дублированные JSON-ключи отклоняются.

## Архитектурные границы

Контроллер отвечает за HTTP-контракт; сервис координирует схему, парсер и генератор. `OpenSearchQueryParser` строит независимый от Spring/Jackson/SQL AST. `ClickHouseSqlGenerator` принимает AST и проверенную таблицу, возвращает SQL и упорядоченные параметры. Ошибки централизованно обрабатывает `@RestControllerAdvice`.

Точные сравнения предполагают подходящие mapping OpenSearch и типы колонок ClickHouse. `LIKE` использует стандартную регистрозависимость выбранной ClickHouse-операции. MVP не обещает совместимость с анализаторами OpenSearch или всем Query DSL.
